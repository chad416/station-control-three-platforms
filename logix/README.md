# Allen-Bradley Logix port

> **Not compiled. Not imported.** No Rockwell software is installed on the machine this was written on. `StationPort.L5X` has never been opened in Studio 5000 Logix Designer, and nothing here has run on a Logix controller or emulator. Whether Logix Designer imports and verifies the file is **not known**.

## What is in the file

`StationPort.L5X` is one controller import file (`TargetType="Controller"`, 1756-L85E, revision 34 written in the header; neither checked). It is generated by `tools/make_logix.py` from `logix/src/*.st` and the CODESYS declarations.

| Item | Content |
|---|---|
| UDT `ST_EvalRecipe` | The evaluation recipe: windows, limits, envelope `EnvLo[64]`, `EnvHi[64]` |
| AOI `AOI_CurveEval` | Curve evaluation. Inputs `Reset Sample Stroke X F Finish`, InOut `Rcp`, outputs as the Siemens block |
| AOI `AOI_HandleStation` | Station sequence. InOut `Rcp` and `CntByCode[32]`. Local tag `Eval` of type `AOI_CurveEval` (nested). Outputs as the Siemens block, plus `E_FpG1` ... `E_XStop` for the screen |
| AOI `AOI_TestPlant` | Bench only: the plant stand-in. InOut test curves |
| Program `BenchProgram`, routine `Bench` | The self-checking bench, in the continuous task `BenchTask` |
| Program `StationProgram`, routine `Station` | The station call and six `ALMD` alarms, in the periodic task `StationTask` (Rate 2 ms; inhibited, so it does not run next to the bench) |
| Controller tags `TD_*`, `TR_*` | Test data (10 curves, 5932 samples each for X and F) and the bench result |

## Rules the port follows, and where they come from

Read in this run: **Rockwell Automation, *Logix 5000 Controllers Add-On Instructions*, publication 1756-PM010I-EN-P, February 2018**, through a public copy at slideshare.net/Hsneves/1756-pm010-enp. Rockwell's own literature and documentation servers refused the request (HTTP 403). Also read, same way: **1756-RM003P-EN-P, *Logix5000 Controllers General Instructions*, December 2014** (slideshare.net/slideshow/1756-rm003-enp/49486775), ALMD pages only. The Import/Export reference manual 1756-RM014 could not be read; its text is not on the public copy that was tried. The L5X element form follows public L5X exports on GitHub (an AOI library, a controller test file of a reader project, a file with an `ALARM_DIGITAL` tag). Those are examples, not a specification.

| Rule | Source | Effect on the port |
|---|---|---|
| Input and Output parameters must be SINT, INT, DINT, REAL or BOOL, passed by value | PM010 p. 43 | Recipe and envelope arrays become an InOut of a UDT; `CntByCode` becomes an InOut `DINT[32]` |
| InOut parameters are passed by reference, can be any type incl. arrays and structures | PM010 p. 43 | `Rcp` is passed down, the station copies it with `COP` at the tare |
| InOut parameters are always required and visible; required parameters need an argument | PM010 pp. 34-35 | Every call passes the instance and the InOuts |
| ST call: instance tag first, then the arguments, e.g. `Motor_Starter(Motor_Starter_ST, Stop_PB, Start_PB, Motor_Out_ST);` | PM010 p. 76 | `AOI_CurveEval(Eval, sRcp);` with the inputs written to `Eval.Reset` ... before the call |
| Parameters are read and written as `Add_On_Tag.Parameter` | PM010 p. 90 | The bench reads `Station.Verdict`, writes `Station.PartPresent` |
| Local tags cannot be reached from outside the AOI | PM010 p. 19 | The screen cannot read `Station.Eval.FpG1`: nine `E_` outputs added |
| Nesting allowed, up to 16 levels from v29, eight recommended | PM010 pp. 28-29 | `AOI_HandleStation` holds `AOI_CurveEval` as a local tag (two levels) |
| AOI names at most 40 characters, descriptions at most 512 | PM010 pp. 41-42 | Checked by `tools/l5x_check.py` |
| Local tag arrays have one dimension | PM010 p. 46 | All arrays are one-dimensional |
| In ST, EnableIn is always true; EnableInFalse never runs | PM010 pp. 59-60 | No EnableInFalse routine |
| Import data types before the AOIs that use them | PM010 p. 99 | UDT first, nested AOI before its user |
| `ALMD(ALMD, In, ProgAck, ProgReset, ProgDisable, ProgEnable);` In: the digital signal; AckRequired, Latched | RM003 pp. 44-46 | Six alarms in `StationProgram`, AckRequired, not latched |
| Arrays have a size, not bounds (`Dimensions="64"`, elements `[0]` ...) | public L5X examples | `ARRAY[1..32]` becomes `[33]`, index 1..32 kept, element 0 unused |

Not from a manual and therefore assumptions: that mixed INT/REAL expressions convert to REAL without a conversion function (`INT_TO_REAL` was dropped), that BOOL literals are written `1` and `0`, that a BOOL array needs a size that is a multiple of 32 (all BOOL arrays get 64), that an `ALARM_DIGITAL` tag may sit in program scope, and the controller and revision in the header.

## Checks done here, and what each one proves

| Check | Command | Result | Proves | Does not prove |
|---|---|---|---|---|
| Well-formed XML | `python -c "import xml.etree.ElementTree as E; E.parse('logix/StationPort.L5X')"` | passes | the file is XML | anything Logix-specific |
| Structural check | `python tools/l5x_check.py` | `StationPort.L5X: 0 findings` (`results/l5x_check.txt`) | the rules in its header hold: parameter types (p. 43), InOut required (pp. 34-35), names, nesting, order, every tag name visible in its scope, every AOI call passes the right instance and argument count | that Logix Designer accepts the file; operand types of instructions; the ALMD rules |
| The checker catches errors | `tests/test_logix.py` | an array Input, a controller tag used inside an AOI and a missing InOut argument are each reported | the checks are not empty | — |
| Interpreter, same 20 cases | `python tools/logix_st.py` | **20 of 20**, largest difference 9.5367431640625e-07, 102 calls (`results/logix_interpreter_bench.json`) | the Structured Text in the L5X, read with the semantics in the header of `tools/logix_st.py` (float32 per operation, INT 16-bit, zero-based arrays, AOI calls as in PM010), gives the same results as the other platforms | that a Logix controller computes the same; Logix REAL rounding, conversion and overflow were not read in a manual and not tested |
| The bench catches a wrong port | `tests/test_logix.py` | turning the release-step comparison round makes the interpreted bench fail | the 20 cases notice a wrong limit check | — |

All checks run in CI.
